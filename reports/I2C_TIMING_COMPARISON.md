## 2. 关键对比

| 指标 | 原 400 kHz 方案（25 kΩ/100 pF） | 内部上拉 400 pF | 内部上拉 1.2 nF |
|---|---|---|---|
| 实测 SCL | **202 kHz** | 70.4 kHz | 26.1 kHz |
| SCL 周期 | 4,950 ns | 14,212 ns | 38,342 ns |
| 上升时间占比 | 61 % | 84 % | 94 % |
| ACK 采样 | ✅ | ✅ | ✅ |
| 单字节事务耗时 | ≈ 9 × 4.95 µs = 44.6 µs | ≈ 128 µs | ≈ 345 µs |
| 16 片 × 7 段初始化估算 | ≈ 5.0 ms | ≈ 14.3 ms | ≈ 38.6 ms |
| 256 通道一帧（16 块 × 64B 突发） | ≈ 16 × 8 × 44.6 µs ≈ 5.7 ms | ≈ 16.4 ms | ≈ 44.2 ms |

> 说明：由于 FSM 会等待 `scl_i` 变高，**标称 400 kHz 永远达不到 400 kHz**，实际频率由
> `4×TICKS + 上升时间裕量` 共同决定。这是一个既有设计特性，非本轮引入。

## 3. 频率上限与总线电容的关系（仿真拟合）

在内部 25 kΩ 下，实测 SCL 近似满足：

```
T_scl ≈ 4 × TICKS × T_clk + t_rise
     = 2.48 µs (标称) + 1.2 × R × C
```

| C_bus | t_rise (25k) | 实测 SCL | 结论 |
|---|---|---|---|
| 100 pF | 3.0 µs | 202 kHz | 可用 |
| 200 pF | 6.0 µs | 124 kHz | 可用 |
| 400 pF | 12.0 µs | 70.4 kHz | 可用 |
| 1.2 nF | 36.0 µs | 26.1 kHz | 可用但慢 |
| ≥1.7 nF | ≥50 µs | — | **触发 SCL 上升超时看门狗** |

## 4. 低速方案的代价

| 项 | 400 kHz 名义 | 10 kHz 配置 |
|---|---|---|
| 256 通道一帧耗时 | ≈ 5.7 ms | ≈ 142 ms |
| 60 秒连续刷新可行性 | ✅ | ⚠️ 帧率降至 ~7 fps |
| 与 STM32 原实现对齐度 | 时序接近 | 偏离原时序 |

**原 STM32 用 250–400 kHz + 4.7 kΩ；KV260 若用 25 kΩ 则实际只有几十 kHz。**

## 5. 结论

1. **内部上拉并非不可用** —— 仿真中从 100 pF 到 1.2 nF 全部能完成 ACK
2. **代价是频率下降**，且下降幅度由电容决定，**不是常数**
3. **不能靠"降低标称频率"来保证** —— 实际上即使标称 400 kHz，硬件也会自动降到能工作的频率
4. 因此 **"改成 10 kHz"对通过性帮助有限**；真正的瓶颈若存在，在别处（器件/接线）
5. 若追求与原 STM32 一致的 400 kHz 实际速率，**仍需外部 4.7 kΩ**

## 6. 仿真局限（必须声明）

- RC 模型是一阶集总模型，**不包含**：传输线反射、地弹、器件输入电容非线性、上拉电阻温漂
- 未建模从机的 ACK 建立/保持时间窗口
- 未建模 SDA 与 SCL 上升时间的差异（本仿真中设为相同）
- **行为模型只能验证时序逻辑，不能替代真实板端上升沿测量**
